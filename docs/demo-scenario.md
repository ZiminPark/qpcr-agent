# 발표 데모 시나리오 (핵심)

한 문장 요약: **복붙 챗봇에 눈 → 손 → 안목 → 노트 → 안전장치 → 동료를 하나씩 붙여, 주간 qPCR 업무를 통째로 맡긴다.**

## 무대 설정

- 화면 좌우 분할: **왼쪽 터미널 = Agent의 뇌** (tool call·판단이 흐름), **오른쪽 대시보드 = 실험실** (기기·곡선·trace)
- 시작 선언 한 번: "기기는 가상, Agent는 실제"
- 발표 전체가 **한 번의 연속된 주간 실험**이다. stage 전환 = 새 디렉터리에서 새 세션. 실험실 상태는 이어진다
- 배경: 협력랩이 매주 RNA 샘플 12개를 보낸다. 우리 일은 검사 → 준비 → 측정 → 보고. 측정에는 RNA 역전사까지 한 번에 수행하는 one-step RT-qPCR 시약을 쓴다
- 발표자 대사(프롬프트)는 각 stage의 슬래시 커맨드에 준비돼 있다

## stage0_chatbot — 아는 건 많은데 손발이 없다

- 구성: MCP 없음. 소품은 `results_week1.csv`
- `results_week1.csv`를 복붙 → "해석해 줘" → **잘한다** (S02의 튄 값도 짚어냄)
- "지금 NanoDrop 연결돼 있어?" → **모른다**. 불편 2개를 심는다: 복붙 지겨움 + 실험실이 안 보임
- 개념: LLM 단독의 한계

## stage1_read — 눈을 달아 준다

- 증분: `.mcp.json` (도구: `read_nanodrop`, `check_devices`)
- "순도 1.8 넘는 샘플만 골라 줘" → tool call JSON을 그대로 보여줌. "생각보다 별거 없죠"
- "NanoDrop 연결돼 있어?" → 이제 답한다 (0단계 불편 2개 모두 회수). 검사(NanoDrop)가 업무의 첫 단계라 다음 대사(합격 샘플 고르기)로 자연히 이어진다
- **명명의 순간**: 목적 + 도구 = **qPCR Agent**
- 개념: Tool Calling (read)

## stage2_write — 손을 달아 준다, 승인이 생긴다

- 증분: 쓰기 도구 2개(`run_liquid_handler`, `reserve_quantstudio`) + 권한 설정(읽기 자동, 쓰기 확인)
- "순도 1.8 넘는 합격 샘플만 골라서, 농도 50 ng/µL·샘플당 총량 50µL로 맞춰 플레이트에 준비해 줘" — 새 세션이라 기준·숫자를 매번 다 불러줘야 한다(이 장황함이 stage4 memory의 밑밥). 이전 stage 대화 재현은 불필요: 실험실 상태는 서버에 이어지고, Agent가 read_nanodrop으로 합격 샘플을 스스로 다시 고른다
- Agent가 희석 계산 → **작업 목록 20건** (합격 10샘플 × 샘플당 2건: 원액+희석액 — 대사에서 이 분해식을 먼저 말해 20이 자기 설명적이게) → **승인 프롬프트** (사람이 표를 보고 허락) → 대시보드에서 핸들러 작동, 플레이트가 채워짐
- 읽기는 틀려도 다시 읽으면 되지만, 쓰기는 시약이 사라진다 — 그래서 승인
- 개념: Tool Calling (write), Human-in-the-loop

## stage3_loop — 시력에서 안목으로 (발표의 클라이맥스 ①)

- 증분: `start_qpcr`, `get_qpcr_curves`
- week1: 검사 → 준비 → 측정이 한 세션에서 바로 이어진다(가공의 "지난주" 없이 흐름이 그대로 완결)
- "qPCR 시작하고 끝날 때까지 지켜봐 줘" → 실제 런 시간을 발표용으로 압축한 **80초 런** (40사이클×2초), 대시보드에 곡선이 차오름
- Agent가 주기적으로 곡선을 읽다가 ~28사이클에 **B3만 평평한 것을 감지** → 잠정 이상으로 표시하고 "런 종료 후 해당 샘플을 재검할까요?"를 스스로 꺼냄 → 그 순간 대시보드 B3이 빨갛게
- 루프의 네 박자: 관찰 → 평가(기준: 곡선이 S자로 올라오는가) → 계획 → 행동
- 개념: Feedback Loop. 순서가 정해져 있으면 workflow, 결과 보고 갈리면 Agent

## stage4_memory — 실험 노트를 쥐여 준다, week2가 시작된다

- 증분: `lab_notebook.md` 하나 (코드 0줄)
- 여기서 **week2 배치를 투입**한다 — week2 플레이트는 실제로 비어 있으므로, 이제부터의 "지난주처럼"은 진짜로 방금 준비 작업을 다시 수행한다
- **새 세션**에서 "지난주처럼 세팅해 줘" → 지난주 = 청중이 방금 stage3에서 본 week1 실측(lot #2508, 3칸 규칙, 기준 GAPDH)을 이미 안다
- 개념: Memory — context window는 오늘의 작업대, 노트는 기억

## stage5_guardrail — 일부러 사고를 쳐 본다

- 증분: 없음 (안전 한계는 처음부터 서버에 있었다)
- week2에서 발표자가 대놓고 위험한 지시: "전 샘플 5배 부피로 다시 준비해" → 필요 ~1,663µL > 잔량 ~1,567µL (초기 1900µL 중 준비 단계 소모 후). 반드시 준비(4단계) 이후에 시연할 것 (신선한 1900µL 상태에서는 통과해버림)
- driver가 **실행 전에 거부** (이유+숫자를 담은 에러) → Agent가 에러를 읽고 계획을 수정
- 개념: 안전은 프롬프트로 부탁하지 않고 층으로 쌓는다 (지시 < 승인 < driver)

## stage6_multiagent — 동료 Agent가 들어온다 (클라이맥스 ②)

- 증분: `.claude/agents/qc-reviewer.md` 하나
- 도입: 실행한 Agent가 자기 결과를 자기가 채점하고 있다 — 오류를 만든 컨텍스트는 그 오류를 못 본다
- **리셋(week2)** 으로 지금까지의 진행분(플레이트, 시약 소모, trace)을 지우고 검사부터 다시 시작 → **최종 무인 완주**: orchestrator(메인)가 worker에게 실험을 위임, **읽기 전용 reviewer**가 신선한 컨텍스트로 채점 — week2에 심어둔 튄 값(ⓑ, 이때까지 미공개)을 reviewer가 잡아냄 → 보고서 완성
- 개념: 역할 분리·권한 경계, 자기 평가(4단계) vs 독립 평가(6단계) = 동료 검토

## stage7_mhs — qPCR Agent에서 Lab Agent로 (구현 보류)

- "기기 7종, 벤더 5곳이면?" → `discover_devices` → 원심분리기·HPLC **카드가 라이브로 늘어남**, 코드 0줄로 원심분리기 조작
- 개념: 표준(MHS). 상세 스펙은 stage0~6 완성 후

## 한 장 매핑

| stage | 불편 | 증분 | 개념 |
|---|---|---|---|
| 0 | 복붙 지겹고 실험실이 안 보임 | — | LLM 단독 |
| 1 | " | 읽기 도구 2개 | Tool Calling (read) |
| 2 | 옮기는 건 나다 | 쓰기 도구 2개 + 승인 | write, HITL |
| 3 | 지켜보는 건 나다 | qPCR 도구 2개 | Feedback Loop |
| 4 | 매번 다시 알려줘야 함 | 노트 파일 1개 (+ week2 투입) | Memory |
| 5 | 알아서 움직이니 불안 | 없음 (시도만) | Guardrail |
| 6 | 자기 채점의 한계 | reviewer 정의 1개 (+ 리셋 후 무인 완주) | Multi-Agent |
| 7 | 기기마다 연동 비용 | discovery | 표준 (MHS) |
